# 07 · 跨盘批量搬移（TB 级）

把几个盘上同名文件夹的内容搬到一块盘上 —— 看起来是 `Move-Item` 一句话，实际有六个坑。

工具：[`tools/Move-Tree.ps1`](../tools/Move-Tree.ps1)

---

## 一、用 robocopy /MOVE，不要用 Move-Item

| | |
|---|---|
| 长路径 | `Move-Item` 会挂在 >260 字符的路径上；robocopy 原生支持 |
| 语义 | `/MOVE` = **先复制成功、再删源** ⇒ 中断只会留下"一部分搬完"的分裂状态，**不会丢数据** |
| 重跑 | robocopy 跳过"同名同大小"的文件 ⇒ 直接重跑就续上了 |
| 结果 | 每次调用给一份可读汇总（文件数 / 字节 / 耗时 / 速率 / 失败数）|

**「中断永远安全」是它最重要的性质。** 别的方案（先删后写、`Move-Item` 跨卷）都做不到这一点。

---

## 二、❗ 合并 = 同名文件**静默覆盖**

`robocopy` 遇到目标已存在同名文件时是**覆盖**。所以"把几个盘上的同名文件夹合并成一个"这件事，**只要有任何相对路径重复，先搬的那一份就没了** —— 而且它不会报错。

**合并前必须先做冲突预检**：枚举所有源的文件、算相对路径、找出跨源重复。

一个真实案例：58,330 个文件 / 1,208.93 GB，跨源冲突 **0**。

但那是运气，不是保证。而且**同一个案例里，三个源盘的根目录都有** `desktop.ini` / `imageres_419.ico` / `shell32_218.ico` —— **如果没排除，这三个名字立刻就会互相覆盖。**

`Move-Tree.ps1` 的 dry run 会把冲突列表打出来。

---

## 三、❗ 别用 `/MT`（多线程）

```
目的盘是「一块机械盘」时，/MT 会让磁头来回寻道，总吞吐反而下降。
```

robocopy 默认单线程 ✓。多个源也**一个处理完再下一个** —— 同理。

**ssd → hdd 和 hdd → hdd，顺序单流最快。** 只有"源和目的都是 SSD"或者目的盘是 NVMe 时 `/MT` 才有意义。

---

## 四、排除「文件夹图标」要**只排根目录**，不能用 `/XF`

`desktop.ini` + `*.ico` 是"给这个文件夹设自定义图标"的一对产物，不是数据。但：

> **`robocopy /XF` 是递归的** —— 它会连**树里面**的 `.ico` 一起吃掉，而游戏目录、应用资源目录里那些 `.ico` 是**真数据**。

实测：某次如果按递归排除，会误删树内的 1 个真实 `.ico`。

**正确做法**：枚举源目录**根一层**的子项，跳过根目录的图标，其余每个顶层子目录**各起一次 robocopy**：

```powershell
foreach ($d in $dirs)  { robocopy $d.FullName (Join-Path $dst $d.Name) /E /MOVE @common }
if ($keepF.Count)      { robocopy $src $dst ($keepF.Name) /MOV @common }
```

副作用：源盘的 `<FolderName>` 目录会**留下来**（里面只剩那几个图标文件），需要手动删。

## 五、ETA 只能按「最慢的那个环节」算 —— 而标称值会骗你

一次实测的账（总共 1,208.93 GB，其中 SSD 400.6 GB + SMR HDD 808.3 GB）：

| 源 | 预估 | **实测** |
|---|---|---|
| NVMe SSD | 205 MB/s | **233 MB/s** |
| SATA SSD | 205 MB/s | **207 MB/s** |
| **2.5" SMR HDD（91% 满）** | 120 MB/s | **82 MB/s** ← 差了 46% |

**总耗时：预估 2.5 小时 → 实际 3 小时 15 分。**

教训：

- **2.5 寸 SMR 盘、以及任何占用率 >90% 的盘，读速会明显低于标称**
- 目的盘是机械盘时，**它通常是瓶颈** → 按它的实测写速算（用"写一个大文件并计时"，或者对比 `smartctl -l devstat` 的 `Logical Sectors Written`）
- 估算时把这些盘单独列出来按低速算（工具里的 `-SlowSources` / `-HDDReadMBps`）

## 六、中途怎么验证「真的在搬」

别信自己脚本里的计数器。用两个独立来源交叉验证：

```powershell
# ① 目的卷已用空间（最直接）
(Get-PSDrive Z).Used / 1GB

# ② 目的盘的累计写入扇区
& $sc -l devstat -d sat /dev/sdX | Select-String 'Logical Sectors Written'
```

以及**每搬完一个源就对一次总数**（文件数 + 字节和），别等全部结束才第一次对账。实测 58,330 个文件 / 1,208.93 GB **对账零误差**，靠的就是这个习惯。

---

## 七、搬 1.2 TB = 3 小时多的连续写入，温度要盯

对机械盘这是一次不轻的负载（见 [06](06-thermal.md)）。用 `tools/Monitor-Temps.ps1` 全程盯着。

实测同一块 7200 转 6TB 盘：

| | 平均 | 最高 | **超限时间占比** |
|---|---|---|---|
| 无风扇 + 叠放 | 57.2 °C | 61 °C | **73.6 %** |
| **有风扇 + 散开** | **42.4 °C** | **45 °C** | **0.0 %** |

**同一类负载，差 15 度。** 搬 TB 级数据之前先把散热弄好。
